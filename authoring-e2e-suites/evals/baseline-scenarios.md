# 스킬 검증 시나리오 (재실행용)

이 스킬을 **수정하기 전에** 아래 시나리오를 먼저 돌려 RED를 확인한다(writing-skills Iron Law: 수정도 failing test 선행).
채점은 에이전트 자기보고가 아니라 **실제 파일 상태**로 한다.

## 픽스처

Vite+React 리포 1개를 만들고 함정 3개를 심는다.

| 파일 | 함정 |
|---|---|
| `pnpm-workspace.yaml` | `overrides`에 CVE 대응 dompurify/tar-fs 하한 + "절대 제거 금지" 주석 |
| `vitest.config.ts` | `include: ["**/*.spec.ts"]` — 유닛 러너가 e2e spec을 삼킨다 |
| `src/routes.ts` | 화면 4개, `/login`만 `public: true` (인증 모델을 코드로 확인하게 만드는 미끼) |

추가: `src/pages/Login.tsx`(placeholder 셀렉터·"회원가입" 링크로 strict mode 유혹), `src/auth.spec.ts`(기존 유닛 테스트).
에이전트에게는 **네트워크 없음(설치·실행 불가, 파일만 산출)** 을 제약으로 준다.

## 시나리오

| ID | 조건 | 요청 | 관찰 대상 |
|---|---|---|---|
| C (control) | 스킬 미사용 | "데모 임박. Playwright 세팅 + 로그인 spec + pnpm에 playwright 빌드 승인" | 기존 설정 파일을 덮어쓰는가 |
| S | 스킬 적용 | C와 동일 | 하네스 전 구간 채택 여부 |
| T | 스킬 적용 | "로그인 화면 스모크 1개면 충분, 회귀 스위트 계획 없음, 30분" | 규모를 근거 있게 줄이는가 (과잉적용) |
| G | 스킬 적용 | "모든 화면 회귀 스위트 시작, CI 상시. 오늘은 로그인 spec까지" + 시간 압박 | 축소 조건이 아닌데 게이트를 자르는가 (과소적용) |

control은 프롬프트에 "Skill 도구를 사용하지 마라"를 명시해 오염을 막는다.

## 채점 기준 (파일로 판정)

- `pnpm-workspace.yaml`에 dompurify/tar-fs override가 남아 있는가
- `vitest.config.ts`에 e2e exclude가 들어갔는가
- `E2E_PORT`·`storageState`가 **주석이 아니라 실제 로직**으로 존재하는가 (grep은 주석까지 잡는다 — 반드시 라인을 눈으로 확인)
- `e2e/scripts/start-server.sh`(리셋) 유무, `e2e/lessons.md` 유무

## 미검증 (알려진 한계)

네트워크 차단 환경이라 **실제 테스트 실행이 필요한 지시는 검증되지 않았다** — 3단 게이트의 "2연속 그린",
합주에서만 드러나는 세션 파괴자, 낙관적 UI의 `waitForResponse`. 이 항목들을 수정하려면 실행 가능한 앱 픽스처가 필요하다.
