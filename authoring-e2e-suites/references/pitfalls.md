# E2E 실전 함정 사전

실제 스위트 구축(16 spec·54 tests, work-note 2026-08)에서 전부 실측된 항목. 증상 → 원인 → 교정.

## 세션·인증

### 스위트 중반부터 401 연쇄 → login 리다이렉트 전멸
- **진단 단서**: 실패가 특정 파일 "이후"에만 몰리는 실행 순서 비대칭 = 그 파일 안에 세션/전역 상태 파괴자가 있다.
- **원인 A — 로그아웃 테스트가 공유 세션으로 로그아웃**: 서버가 그 세션을 무효화 → storageState 쿠키 전면 무효.
- **원인 B — API 로그인 헬퍼가 공유 storageState를 상속**: 전역 `request.newContext()`의 기본값은 프로젝트 `use.storageState`. 같은 세션 id로 재로그인하면 서버의 세션 고정 방어(session-fixation, changeSessionId)가 id를 회전시켜 공유 쿠키가 죽는다.
- **교정**: 세션 변이 시나리오는 빈 storageState 컨텍스트에서 자체 로그인. 헬퍼에는 `storageState: {cookies:[],origins:[]}`를 하드코딩해 **함정을 API 형태로 제거**(주석 경고는 두 에이전트가 독립적으로 무시했다).

### 시딩 API가 403 (invalid_origin / CSRF)
- 변경 메서드(POST/PUT/PATCH/DELETE)에 Origin/Referer 검증을 하는 백엔드가 흔하다. APIRequestContext에는 Origin이 자동으로 안 붙는다.
- **교정**: `extraHTTPHeaders: { Origin: baseURL }` 명시. UI 세션으로 시딩할 땐 `page.request` 사용(쿠키 자동 공유) + Origin 헤더.

### 통념 기반 기대는 틀린다
- "공유 링크는 공개"라고 가정했다가 실제로는 로그인 필수(설계 결정)였던 사례. 기능의 인증·접근 모델(필터 allowlist, 미들웨어)을 **코드로 확인한 뒤** 기대를 써라.

## 하네스·환경

### dev 서버와 프로덕션 빌드의 기능 플래그가 다르다
- dev 모드가 스토리지/인증 모드를 다르게 타서 화면 절반(공유·휴지통·로그아웃·첨부)이 아예 렌더되지 않았던 사례. 서빙 결정을 spec 작성 전에.

### 상태 리셋은 webServer 커맨드 안에서
- globalSetup ↔ webServer 실행 순서는 버전별로 신뢰 불가. 기동 스크립트가 "리셋 → exec 서버"를 하면 순서 문제가 소멸한다.

### 유닛 러너가 e2e 파일을 삼킨다
- vitest/jest 기본 include가 `*.spec.ts`를 잡는다. e2e 디렉토리를 exclude(또는 파일명 규칙 분리)하고 유닛 테스트 실행으로 검증.

### 기존 설정 파일 덮어쓰기 사고
- pnpm-workspace.yaml을 신규로 알고 생성했다가 기존의 보안 override(dompurify 플로어)를 날린 실사례. **생성 전 존재 확인 → 있으면 읽고 병합.** 커밋 전 git status에서 신규로 기대한 파일이 `M`이면 즉시 diff.
- 부수: pnpm 11+는 package.json `pnpm` 필드를 읽지 않는다(설정은 pnpm-workspace.yaml). 간접 의존성 바이너리는 `pnpm exec`에 없으므로 승인 여부는 실제 빌드 성공으로 판정.

### 서버 모드의 저장소 검증
- 보안 강화된 앱은 DB 절대 경로·디렉토리 권한(700)을 기동 조건으로 요구할 수 있다. `/tmp`(1777)가 거부되는 케이스 — 러너 소유의 runtime 디렉토리를 만들어 chmod.

## 시나리오 작성

### 낙관적 UI: 화면 반영 ≠ 서버 반영
- 생성/수정/삭제가 fire-and-forget이면 reload 검증 전에 해당 mutation의 응답을 `waitForResponse`로 대기.

### 자동 등장 UI·상태 의존 라벨
- 유예 배너·공지 모달이 첫 진입에 뜨는 앱: 각 테스트가 안전하게 처리(존재 전제 or dismiss).
- 같은 섹션이 상태별로 다른 제목을 갖는다(예: 2FA idle vs setup). 렌더 분기 **전체**를 읽고 라벨을 골라라 — 첫 grep 매치로 단정 금지.

### 동일 문구·중복 요소 (strict mode 위반)
- 전환 링크와 제출 버튼이 같은 문구인 폼 → 클래스/역할로 구분.
- 짧은 수명 토스트가 스로틀 틈새로 2개 겹치는 케이스 → `.first()`.
- 폼 모드 전환(로그인↔가입)으로 입력 인덱스가 변한다 → placeholder/type 셀렉터.

### UI 상태는 서버에 없다
- 트리 접힘/펼침 같은 UI 상태는 reload 후 초기화된다. 접힌 컨테이너 안에 요소를 만들면 렌더 자체가 안 됨 → 먼저 펼쳐라.

### 테스트 데이터의 부작용
- 이메일·전화번호·주민번호 형태 문자열이 PII 스캐너류를 트리거해 배너/모달로 화면을 바꾼다. 타임스탬프 base36 접미사 같은 중립 문자열 사용 (그 기능을 검증하는 테스트 제외).

### 전역 설정 변이는 무조건 원복
- 업로드 정책 같은 앱 전역 설정을 바꾸는 테스트: beforeAll 원본 캡처 + afterAll 무조건 원복. 중간 실패가 다른 spec으로 누출되는 것을 막는다.

### headless 한계
- OS 단축키(⌘/Ctrl+S 등)가 앱 window keydown까지 안 오는 경우 실측 → 같은 코드 경로의 버튼 클릭으로 대체. 클립보드 검증 금지 — 값은 생성 API 응답이나 DOM에서.

## 병렬 서브에이전트로 spec 작성을 나눌 때

- **격리 파라미터화(포트 스코프의 DB·storageState·리포트 경로)를 투입 전에** 하네스에 넣는다.
- 에이전트는 자기 파일만 실행(전체 실행 금지 — 타 에이전트의 미완성 spec이 섞인다), 데이터 이름은 유일 접미사.
- 보고서에 "실제로 틀렸다 고친 것"을 의무 항목으로 — 도착 즉시 공용 lessons.md에 병합해 진행 중인 에이전트의 같은 실수를 막는다.
- 에이전트 전원 그린이어도 **합주 게이트는 리드가 별도로** 돈다(단독그린≠합주그린).
